# v0.9.3 iBar/Ice 交互收敛

## 对标结论

iBar 的聚合模式是“隐藏项目在菜单栏下方集中展示”，而不是让每个项目用可见的鼠标拖动动画在第一行来回穿梭；Ice 的模型则是持续维护 Visible / Hidden / Always-hidden 三个区段，通过边界状态切换显示隐藏项目。两者都把布局变化当作内部状态，不把 Command 拖动过程暴露给用户。

## 本轮修复

- 原始菜单栏项目的 Command 拖动改为单个目标位置事件，不再发送 10 个插值拖动点。
- 取消 180ms 的“画图式”拖动过程，减少相邻状态栏项目反复重排。
- 保留收回结果校验和重试，点击项目后最终仍以 Hidden 区状态为准。
- 不改变 iBar 式“收纳篮显示真实菜单栏项目”的产品模型，也不把项目图标改成应用图标。

## 交互验收

1. 悬停 TuckBar 触发器，收纳篮在菜单栏下方出现。
2. 点击某个收起项目时，顶部不应出现持续的鼠标拖动动画。
3. 原生菜单关闭后，项目应回到收纳篮，不能留在第一行。
4. 连续点击两个不同项目时，第二次不能复用第一次的目标。

参考： [iBar 聚合模式](https://www.better365.cn/ibar.html)、[Ice 菜单栏管理器](https://icemenubar.app/)。
