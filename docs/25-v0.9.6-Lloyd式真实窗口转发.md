# v0.9.6 Lloyd 式真实窗口转发

## 问题根因

v0.9.4/v0.9.5 曾尝试通过 macOS Accessibility 的 `AXUIElementPerformAction` 直接按隐藏项目。macOS 26 的很多菜单栏项目由 Control Center 代托管：辅助功能树可以返回项目和位置，但 `AXPress`/`AXShowMenu` 不保证真的打开原菜单。于是收纳篮点击会出现“图标闪回、菜单不打开、点击后无法收回”等状态错乱。

## 对标实现

[Lloyd](https://github.com/benwbooth/lloyd) 的实现验证了更可靠的路径：先通过 Command 拖动把单个项目拉到可见槽位，再向该真实窗口发送带窗口 ID 和进程 ID 的合成点击，最后等待窗口位置稳定。项目源码特别处理了拖动期间不能立刻 warp 鼠标的问题，并在操作结束后恢复鼠标位置。

## 本轮改动

- 收纳篮点击不再展开整段隐藏区，只移动被点击的单个窗口。
- Command 拖动发送起点、中点、终点三个阶段，并绑定 `eventTargetUnixProcessID`、`mouseEventWindowUnderMousePointer` 和窗口 ID 字段。
- 拖动和点击期间隐藏系统光标，避免用户看到“鼠标把图标画出来”的动画。
- 通过 WindowServer 的 `SetsCursorInBackground` 连接属性，让后台菜单栏应用也能可靠隐藏和恢复光标；不再依赖前台应用行为。
- 移动后轮询窗口帧，确认窗口已经移动并稳定，再发送点击。
- 点击后保留原生菜单约 1 秒，再把同一个窗口移回 Hidden 区；收回后重新扫描确认它不再出现在第一行。
- 删除未使用的 AX 直接按压路径，避免未来再次误用不可靠的激活方式。

## 验证

- Debug 构建：`xcodebuild ... CODE_SIGNING_ALLOWED=NO build` 通过。
- Release 交付：使用 `scripts/package-stable.sh` 生成唯一的 `dist/TuckBar.app` 和 `dist/TuckBar-0.9.6-alpha.zip`。
- 由于真实菜单栏事件依赖用户当前桌面、屏幕录制权限和辅助功能授权，最终点击验证需要在用户机器上从 `dist/TuckBar.app` 启动后执行。
