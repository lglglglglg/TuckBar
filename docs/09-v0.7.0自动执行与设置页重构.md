# v0.7.0 自动执行与设置页重构

> 日期：2026-09-09

## 对应用户反馈

1. 聚合条只有问号，没有真实菜单栏图标。
2. 已选择隐藏的项目仍长期显示在原菜单栏。
3. 设置窗口仍是开发诊断表单，与 iBar 的产品化设置界面差距明显。

## 修复内容

### 隐藏自动生效

- 应用启动并完成首次发现后，若辅助功能已授权且本地保存了收纳项目，会自动恢复隐藏布局。
- 用户在“菜单栏布局”页面修改常显、隐藏或始终隐藏状态后，立即执行布局，不再要求额外点击“应用隐藏设置”。
- 应用从系统授权页面重新回到前台时，若布局尚未生效，会自动再次执行。
- 增加执行互斥，避免启动恢复和设置修改同时发起两轮 Command 拖动。

### 在隐藏前缓存真实图标

- 应用布局时，先让项目保持可见，并调用 ScreenCaptureKit 获取普通隐藏区项目的真实窗口快照。
- 快照写入聚合面板内存缓存后再执行隐藏。
- 后续打开聚合条直接使用缓存，不再等到项目已经被移出屏幕后才尝试截图。
- 屏幕录制未授权时仍保持有限模式，不会自动触发系统授权弹窗。

### iBar 式设置结构

设置窗口改为产品化的左侧导航与右侧内容区：

- 通用设置：悬停打开、立即打开聚合条。
- 授权：辅助功能和屏幕录制分开解释并显示状态。
- 菜单栏布局：所有项目的三态分区和即时应用。
- 使用教程：三步完成授权、分区和打开。
- 关于：版本、系统要求和本地数据说明。

窗口使用透明标题栏、左侧导航和半透明渐变卡片，整体信息架构以用户提供的 iBar 设置截图为基准。

## 关于屏幕录制授权

本机当前没有可用的 Apple Development 或 Developer ID 代码签名证书，测试包只能使用 ad-hoc 签名。即使 Bundle ID 和 designated requirement 固定，替换二进制后 macOS 仍可能把屏幕录制授权视为新的代码主体。

因此当前 Alpha 每次更换构建后，可能需要在“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”中重新开启当前固定路径的应用，并彻底退出、重新启动一次。正式发布前必须改用稳定的开发者证书签名，这一问题才能从根本上消失。

## 验证重点

1. 退出旧进程后启动 `dist/MenuBarOrganizer.app`。
2. 检查设置页是否显示辅助功能和屏幕录制均已授权。
3. 如果屏幕录制显示未授权，重新开启固定版本权限并重启应用。
4. 打开“菜单栏布局”，把两个项目设为隐藏；不点击其他按钮，确认几秒内原图标自动离开顶部。
5. 点击双箭头，确认第二行显示原图标而不是问号。
