# v0.3.0 产品模型重构

## 为什么重构

早期原型把“扫描到的窗口”当成了“用户要收起的项目”，并用所属应用图标代替菜单栏图标。这会造成两个明显问题：

- 系统菜单栏里实际只看得到少数项目，但面板里却列出一大批扫描结果；
- 应用图标并不等于菜单栏项目的实时状态，无法表达数字、进度、电量或应用自定义图形。

这与 iBar、Ice 的核心逻辑不一致。它们管理的是原始菜单栏状态项，而不是应用启动器。

## v0.3.0 的新模型

1. `discoveredItems`：当前显示器上通过 Accessibility 和窗口几何关系识别出的、可管理的原始菜单栏项目。
2. `hiddenItemIdentifiers`：用户明确选择要收起的项目，保存在本机 UserDefaults，和一次扫描结果分离。
3. 聚合面板：只显示 `hiddenItems`，它是隐藏项目的查看/点击入口，不是“所有扫描到的应用列表”。
4. 菜单栏入口：只保留一个收纳工具自己的入口，不再绘制额外分割线，也不把分割线当作隐藏区边界。
5. 图标语义：优先使用原始菜单栏窗口快照；无法抓取时显示明确的占位符，不再使用所属应用图标冒充原始状态。

## 当前完成范围

- 设置页可以展示当前显示器的可管理项目。
- 用户可以逐项加入或移出隐藏列表。
- 聚合面板只渲染隐藏列表中的项目。
- Screen Recording 未生效时不会重复调用捕获 API 触发系统权限提示。
- 已移除旧的“扫描数量 = 面板数量”以及“应用图标 fallback”逻辑。

## 尚未完成的执行引擎

当前版本已经完成产品模型和 UI 边界重构，但还没有宣称“已经把原始图标从系统菜单栏移走”。下一阶段需要实现：

- 以 `sourcePID + WindowID/稳定状态项身份` 建立可持久化、可区分同一应用多个状态项的标识；
- 在 WindowServer/Accessibility 允许的范围内，把选中的原始状态项移动到隐藏区域并支持恢复；
- 将原始菜单项的点击事件可靠转发给来源应用；
- 处理应用重启、显示器切换、菜单栏布局变化和权限撤销。

因此，v0.3.0 的“隐藏”在设置和数据模型层面已经成立；系统级实际收起仍是下一阶段工程，不应通过应用图标或分割线模拟完成。
