# v0.7.3 验证记录（2026-09-15）

- 修复扫描和隐藏引擎混用 AppKit / Core Graphics 屏幕坐标的问题；用 CGDisplayBounds 定位显示器。
- 边界候选限定在目标菜单栏同一高度，降低跨显示器误匹配。
- 收纳完成状态要求所有目标移动验证成功；通用设置显示实际操作结果。
- 当前执行引擎依赖窗口名称识别边界。未获得屏幕录制权限时暂停执行，并展示原因；打开聚合条回到设置，不展示一排问号或反复请求权限。
- 快照刷新失败保留已有原图缓存。

## 实机证据与未完成验收

Release 构建及签名校验通过，0.7.3 能启动。当前连接一块 1512×982 显示器；辅助功能已授权，屏幕录制在应用内检测为未授权。初次实测仍有目标图标留在顶栏，因此不能宣称隐藏功能已通过验收。

下一步需用户为 dist/MenuBarOrganizer.app 的当前二进制授权屏幕录制并重启应用，再验证窗口坐标、真实图标快照和点击回传。尚未验证多屏重连。固定路径与临时签名不保证每次重新构建后系统权限自动继承。

## 授权持续失效与启动收纳补充

已核实当前签名为 adhoc，且 security find-identity 返回 0 个可用签名身份。Apple DTS 在 https://developer.apple.com/forums/thread/819406 确认临时签名重建可导致屏幕录制权限失效；目前这是已发现的发布流程缺陷，尚不能据此排除其他系统权限问题。

- 新发现的第三方菜单栏项目默认加入收纳；系统项目保持常显，用户之后明确设置的常显例外会保存。
- 启动延迟扫描后直接尝试应用，权限不足显示实际原因。授权入口同时打开系统对应设置页，说明如何移除旧记录并添加当前包。
- package-stable.sh 支持 MENU_BAR_SIGNING_IDENTITY 指定本机已安装的证书；不配置时仍为临时签名，不能保证升级后保留授权。
- 需要用户先配置 Apple Development 证书才能完成稳定签名。没有创建证书、修改钥匙串信任或重置任何系统授权。

## 授权重置后的实机结果

随后仅对 com.hanshijiu.MenuBarOrganizer 执行 ScreenCapture 重置，用户重新打开系统授权。当前固定应用确认辅助功能和屏幕录制均已授权。启动自动整理已运行，界面报告移动验证成功 4/7 项；系统窗口坐标亦显示多个第三方项目位于负坐标、不可见。

权限阻塞已解除，功能尚未完整验收：剩余项目移动验证失败的原因仍需排查，不能直接断定项目不支持拖动。聚合条原图和点击回传尚未确认。此阶段不重新打包，保留刚获得授权的二进制。
