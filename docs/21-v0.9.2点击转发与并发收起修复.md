# v0.9.2 点击转发与并发收起修复

## 用户可见问题

- 鼠标悬停打开收纳篮后，点击某个项目会出现指针像被自动移动、收纳篮反复开关的感觉。
- 点击一个项目后，原始菜单栏项目会短暂全部回到第一行；有时第二次点击仍会激活第一次的项目。

## 根因

1. 点击转发完成后，旧实现额外发送了一个合成 `mouseMoved` 事件，把鼠标事件流重新注入到收纳篮触发区，导致悬停状态被误判。
2. 项目激活是异步的。第一次项目仍在 Command 拖动、原生点击和回收流程时，第二次项目可以再次启动另一套拖动流程；两个流程会读取到不同时间点的窗口坐标，形成错误目标。
3. 点击完成后的回收流程再次展开整个隐藏区，造成全部原始图标闪回。

## 修复

- 点击原始菜单栏项目只发送目标位置的 mouse-down/mouse-up，不再发送合成鼠标移动或恢复鼠标位置事件。事件位置不会改变用户真实指针。
- 增加单项目激活事务锁：一个项目未完成前，禁止新的悬停打开、重复点击和并发 Command 拖动。
- 激活结束后保持隐藏区收起，直接把当前项目拖回隐藏边界，不再二次展开所有已收起项目。
- 仍按持久标识重新扫描目标项目，避免使用收纳篮第一次展示时的旧窗口坐标。
