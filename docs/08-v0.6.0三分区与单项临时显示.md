# v0.6.0 三分区与单项临时显示

> 日期：2026-09-09  
> 阶段：iBar 聚合模式执行内核第二阶段

## 本轮目标

把 v0.5.0 的“外观像聚合条”推进到真实的菜单栏管理模型：菜单栏项目具有常显、隐藏、始终隐藏三种位置；点击聚合条中的某一项时，工具尝试只临时恢复这一项，而不是让整组隐藏项目停留在顶部。

## 已完成

### 三种项目状态

- **常显**：位于可见边界右侧，始终留在原菜单栏。
- **隐藏**：位于两个内部边界之间；收起后不在顶部显示，但会进入第二行聚合条。
- **始终隐藏**：位于最左侧边界之外；不会出现在第二行聚合条。

原 v0.5.0 的隐藏项目标识继续沿用，不需要用户重新选择。始终隐藏使用独立的本地持久化集合。

### 双边界执行引擎

执行引擎现在创建两个不可见的 `NSStatusItem` 控制边界，并为触发器及两个边界配置稳定的 `autosaveName`：

- 可见区 / 隐藏区边界；
- 隐藏区 / 始终隐藏区边界。

边界本身没有可见图标，不是产品 UI 中的分割线。它们只负责保持 macOS 菜单栏项目的相对分区。

收起时使用固定 10,000 pt 占位长度，把两个收纳区一起推离屏幕；展开普通隐藏区时，始终隐藏边界保持 10,000 pt，因此始终隐藏项目不会跟着出现。

### 单项临时显示

点击聚合条图标后的当前流程：

1. 暂时开放普通隐藏区，始终隐藏区继续收起。
2. 找到被点击项目的最新真实窗口。
3. 用 macOS 原生 Command 拖动规则把该项目移动到可见区。
4. 立刻重新收起普通隐藏区，因此顶部只留下目标项目。
5. 对目标项目发送原生点击。
6. 保留约 1.1 秒的原生操作时间。
7. 再次开放隐藏区，把目标项目移回隐藏区并收起。

这一阶段仍使用固定延迟。后续需要通过辅助功能窗口/菜单状态识别，改成“菜单真正关闭后再收回”。

## 设置窗口变化

项目右侧从单个开关改为三态菜单：常显、隐藏、始终隐藏。窗口分别显示聚合面板数量和始终隐藏数量。

## 验证结果

- Debug 应用构建通过。
- `build-for-testing` 通过，说明应用与测试目标均能完成编译链接。
- 完整测试运行仍受当前环境 `testmanagerd` 沙箱连接限制，需在普通桌面会话或 Xcode 内执行。
- Release 为 arm64 + x86_64 通用二进制，并继续使用固定 Bundle ID 和 designated requirement，避免权限主体随构建路径变化。
