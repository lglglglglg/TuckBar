# iBar 主交互与 Ice 能力融合规格

> 日期：2026-09-09  
> 结论：产品日常体验以 iBar 聚合模式为翻版基准，Ice 只补充能力与公开工程思路。不得再自行发明卡片式应用列表、标签式图标面板或独立启动器逻辑。

## 1. 一句话产品定义

这是一个 macOS 菜单栏项目收纳工具：把真实菜单栏项目移出可见区域，并通过菜单栏触发器在下方显示一条紧凑的第二行菜单栏；用户点击第二行里的图标时，应用临时恢复并操作对应的原始菜单栏项目。

“菜单栏项目”是系统状态项本身，不等于所属应用。面板必须优先显示状态项当前画面，不能拿应用图标代替。

## 2. 为什么以 iBar 为主

iBar 的官方产品页明确提供两种模式：普通模式在原菜单栏内收起/展开，聚合模式把隐藏项目放到菜单栏下方的悬浮条中。[1] 对带刘海的 MacBook，聚合模式比强行在原菜单栏内展开更稳定，也与本项目的真实问题完全一致。

iBar 的聚合模式形成了一条非常清楚的操作链：

1. 用户指定哪些原始菜单栏项目需要隐藏。
2. 隐藏后，顶部只保留 iBar 触发器和常显项目。
3. 点击或悬停触发器，菜单栏下方出现单行图标条。
4. 面板只显示原始菜单栏图标，不显示应用名称、Bundle ID、开关或大卡片。
5. 点击面板图标时，原项目临时回到菜单栏并打开自己的原生菜单。
6. 延迟结束或操作结束后，原项目再次隐藏。

iBar 还提供始终隐藏区、项目顺序、间距、触发器样式和收回延迟等设置。[2] 这些都属于菜单栏管理的必要能力，而不是额外创意。

## 3. Ice 要吸收的优点

Ice 的优势不在于改变 iBar 式主界面，而在于管理能力更完整：它支持隐藏区与始终隐藏区、点击/悬停/滚动触发、自动重新隐藏、拖放布局、独立 Ice Bar、搜索、快捷键和菜单栏外观控制。[3]

本项目吸收以下能力：

- 三段状态：常显、隐藏、始终隐藏。
- 点击、悬停、滚动和全局快捷键四种打开方式。
- 自动收回，可配置延迟；打开原项目菜单时不能粗暴收回。
- 独立的布局编辑器，直接管理真实菜单栏项目的位置。
- 多显示器分别定位面板，并记录当前屏幕。
- 搜索隐藏项目。
- 无屏幕录制权限时仍可执行基础收起/展开，只禁用原图快照和依赖图像的界面。

Ice 0.11.12 已加入无屏幕录制权限的有限模式；其 macOS 26 测试版说明 Apple 改动了菜单栏机制，并明确列出项目移动、临时显示位置、菜单打开期间错误收回、名称和图标识别等兼容问题。[4] 因此这些不是“后续再说”的边角问题，而是执行引擎的验收项。

## 4. 两款产品对标表

| 维度 | iBar | Ice | 本项目决定 |
| --- | --- | --- | --- |
| 主体验 | 普通模式 + 聚合模式 | 原栏展开 + Ice Bar | 默认复刻 iBar 聚合模式 |
| 第二行视觉 | 单行、紧凑、只显示图标 | 单行、紧凑、支持宽状态项 | iBar 外形，兼容 Ice 的宽项目 |
| 点击图标 | 临时把原项目放回菜单栏再操作 | 临时显示单项并触发 | 必须操作原项目，不做应用启动器 |
| 分区 | 显示、隐藏、始终隐藏 | 显示、隐藏、始终隐藏 | 三分区 |
| 触发 | 图标点击/悬停，可设仅点击显示 | 点击、悬停、滚动、快捷键 | 首版点击+悬停，随后补齐 |
| 排序 | 偏好设置内拖放 | 菜单栏布局编辑器拖放 | 最终采用真实项目布局编辑器 |
| 权限 | 辅助功能负责移动；屏幕录制负责图标截图 | 屏幕录制可进入有限模式 | 权限分层、禁止重复弹窗 |
| 系统支持 | App Store 标注 macOS 10.12+，Intel/Apple Silicon | macOS 14+ | 当前保持 macOS 14+ |
| 商业方式 | 免费下载、聚合能力内购 | GPL-3.0、免费、捐赠 | 暂不决定商业模式 |

## 5. UI 不可偏离项

聚合条必须是第二行菜单栏，而不是窗口里的“项目列表”。具体约束：

- 高度约 40–44 pt，圆角约 8–10 pt。
- 单行横向排列；内容过宽才允许横向滚动。
- 图标使用原状态项快照的实际宽度；普通图标约 22 pt 高。
- 无永久标题、应用名、数量角标、卡片底板和问号占位卡。
- 鼠标悬停单项时只出现非常轻的背景反馈，名称放在系统 tooltip。
- 面板贴在菜单栏下方，并与触发器或右侧可用区域对齐；不能漂浮到屏幕中央。
- 点击空白区或鼠标离开后自动关闭；原生菜单正在使用时不应提前收回。

设置窗口不属于日常主界面。应用启动后只驻留菜单栏；右键触发器进入设置。首次启动向导只解释三件事：移动项目需要辅助功能、显示原图需要屏幕录制、如何用 Command 拖动或布局编辑器分区。

## 6. 权限与图标机制

iBar 官方权限说明将辅助功能用于自动移动/显示/隐藏菜单栏图标，将屏幕录制用于截取菜单栏图标并放进聚合窗口。[5] Better365 文档进一步说明 macOS 没有直接取得所有菜单栏应用图标的公开接口，因此需要截图。[6]

由此确定：

- 屏幕录制不是收起动作的必要权限，而是“还原真实图标”的增强权限。
- 未授权时不得循环调用授权 API；只显示一次明确入口。
- 首次成功截图后缓存最后一张可用快照，避免每次打开面板都先展开整组项目。
- 动态图标需要在原项目可见时刷新，静态图标复用缓存。
- 识别失败时显示克制的不可用状态，不得以所属应用图标冒充。

## 7. 执行引擎方向

Ice 的 GPL-3.0 源码可用于理解机制，但不能在闭源产品中直接复制。其公开实现显示，控制项会保留稳定的 autosave 名称，并通过超长状态项占位把某一区域的项目挤出屏幕；隐藏分隔控制项不是删除，而是收缩到不可见宽度，以免破坏分区关系。[7]

本项目需要独立实现同类行为：

1. 建立可见区、隐藏区、始终隐藏区三个稳定位置，而不是每次打开设置再扫描应用列表。
2. 为控制项设置稳定 autosaveName，保证重启后的相对顺序。
3. 收起时使用足够大的占位长度，不用“显示器宽度乘二”这种经验值。
4. 打开聚合条时不展开整组原项目；只显示缓存快照。
5. 点击单项时只临时恢复该项目，发送原生点击，等待其菜单关闭后再还原。
6. macOS 26 的项目来源识别应采用持久 PID/状态项身份缓存；必要时拆到 XPC 服务，隔离不稳定的系统查询。
7. 空闲时采用事件驱动，CPU 应接近 0；不得持续高频全屏扫描。

## 8. 当前项目差距与重构顺序

### P0：做成真的 iBar 聚合模式

- 菜单栏代理应用：启动不弹设置、不占 Dock。
- 紧凑单行原图标条，贴菜单栏定位。
- 点击和悬停触发，离开自动关闭。
- 快照缓存，消除每次打开前整组图标闪现。
- 点击单项时临时恢复原项目并打开原生菜单。
- 权限预检与有限模式，不重复弹屏幕录制申请。

### P1：补齐真实管理模型

- 三分区和两个稳定控制边界。
- 真实菜单栏布局编辑器，而不是应用名称+开关列表。
- 菜单打开感知的自动收回。
- 多显示器分别定位与状态恢复。
- 登录启动、快捷键、打开延迟和收回延迟。

### P2：吸收 Ice 的效率功能

- 搜索、滚轮触发、单项快捷键。
- 项目间距与配置档案。
- 宽状态项和动态状态项的差异刷新。

## 9. 本轮 v0.5.0 已执行

- 改为菜单栏代理应用，启动不再自动打开设置窗口。
- 双箭头作为菜单栏触发器；点击或悬停约 180 ms 打开聚合条。
- 鼠标离开触发器和面板约 420 ms 后自动关闭。
- 聚合条改为右侧贴齐触发器，位于菜单栏正下方。
- 面板保持单行原图标展示，不增加文字卡片。
- 加入内存快照缓存；已有快照时不再为打开面板先展开全部项目。
- 原项目点击后的临时显示时间延长，降低菜单还没打开就被收回的概率。
