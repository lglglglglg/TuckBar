# v0.8.5 收纳面板状态一致性修复

## 问题

旧流程在首次打开收纳面板时，会先展开真实菜单栏项目进行截图，同时立即显示聚合面板，造成同一批图标在菜单栏和面板中重复出现。历史扫描结果也只增加、不淘汰，已经退出或无法继续识别的项目会以问号占位残留。

点击和悬停还可能同时创建打开任务；关闭操作无法可靠取消仍在等待的任务，容易留下菜单栏已经展开、面板随后又出现的中间状态。

## 修复后的状态顺序

1. 展开隐藏区，仅用于读取当前真实项目和截图。
2. 更新当前扫描结果，完整扫描会清理失效项目。
3. 完成截图缓存。
4. 收起真实菜单栏项目。
5. 等待菜单栏完成布局后，再显示聚合面板。

面板只展示已经取得真实快照的项目，不再用问号图标冒充原始菜单栏图标。

## 并发约束

- 同一时间只允许一个面板展示任务。
- 再次点击、鼠标离开、应用隐藏设置和退出应用都会取消未完成的展示任务。
- 被取消的旧任务使用唯一标识隔离，不能清除或覆盖后续新任务的状态。
- 任何取消路径都会恢复已配置的收起布局。
